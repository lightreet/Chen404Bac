# 博客分类添加方式与权限设计

## 一、当前项目现状

### 1. 写文章时的分类使用方式

- 文章编辑页 [Chen404Fro/src/views/Article/ArticleEdit.vue](Chen404Fro/src/views/Article/ArticleEdit.vue) 中，分类是一个**仅可选择**的下拉框：
- 数据来自 `getCategories()`（即 `GET /api/categories`）。
- 使用 `el-select`，**没有** `allow-create`，因此无法在写文章时输入并创建新分类。
- 标签则不同：同一页的标签使用了 `filterable` + `allow-create`，写文章时可以输入并“新建标签”。

### 2. 后端能力

- [Chen404Bac/src/main/java/com/chen404/controller/CategoryController.java](Chen404Bac/src/main/java/com/chen404/controller/CategoryController.java) 仅提供：
- `GET /categories`：获取所有分类（供首页/分类页/文章编辑使用）。
- **没有**“管理员分类”相关接口：没有 `POST/PUT/DELETE /admin/categories`，也没有 `AdminCategoryController`。
- [Chen404Bac/src/main/java/com/chen404/service/CategoryService.java](Chen404Bac/src/main/java/com/chen404/service/CategoryService.java) 只有 `getAllCategories()`，没有 create/update/delete。

### 3. 前端“分类管理”入口

- 个人中心 [Chen404Fro/src/views/Profile/Profile.vue](Chen404Fro/src/views/Profile/Profile.vue) 左侧有菜单项「分类管理」。
- 点击后进入的是占位内容（“功能开发中”），**并未实现**真正的分类列表与增删改。
- 前端 [Chen404Fro/src/api/article.ts](Chen404Fro/src/api/article.ts) 已定义 `createCategory`、`updateCategory`、`deleteCategory`，并请求 `/admin/categories`，但后端目前没有对应接口，调用会 404。

### 4. 小结

| 能力           | 现状说明 |
|----------------|----------|
| 写文章时选分类 | 只能从已有分类中选择，不能新建。 |
| 在哪里新建分类 | 无入口：后端无管理接口，前端“分类管理”仅为占位。 |
| 谁可以建分类   | 未实现，需在方案中确定（仅管理员 / 或写文章时可建）。 |

因此：**目前无法在项目里“添加一种全新的分类”**；要支持添加，需要先选好“谁可以建、在哪里建”，再补后端接口与前端页面/交互。

## 二、方案选择（由你决定）

分类和标签的常见区别是：**分类**通常数量少、用于导航/聚合，**标签**可以很多、由作者自由打。所以一般有两种做法：

### 方案 A：仅管理员定义分类（推荐）

- **谁可以添加/编辑/删除分类**：仅管理员。
- **在哪里操作**：在「分类管理」中完成（个人中心左侧已有入口，或后台管理页）。
- **写文章时**：只从现有分类中选择，不提供“新建分类”；若暂无分类，可提示“请先在分类管理中添加分类”（并可仅对管理员显示“去添加”的入口）。
- **优点**：分类表干净、命名统一，便于全站导航与统计；与当前“标签可自由创建、分类需管理”的常见博客设计一致。
- **需要做的**：后端增加管理员分类 CRUD（如 `AdminCategoryController` + Service 层），前端实现「分类管理」页（列表 + 新建/编辑/删除），文章编辑页保持仅选择并可加空状态提示。

### 方案 B：写文章时可新建分类（类似标签）

- **谁可以添加**：登录用户（或仅管理员，可配置）在写文章时即可创建新分类。
- **在哪里操作**：在文章编辑页的分类下拉中支持“输入新名称并创建”（例如 `el-select` 的 `allow-create` + `filterable`，或“添加新分类”按钮 + 弹窗）。
- **优点**：写文章时不用切到别处即可用上新分类。
- **缺点**：容易产生大量相似分类（如“技术”“技术随笔”“Tech”），不利于导航和统计；若开放给所有作者，需考虑权限与命名规范。
- **需要做的**：后端提供“创建分类”接口（可仅限管理员，或所有登录用户）；文章编辑页分类选择支持“新建一条并选中”。

## 三、推荐结论与实现要点（按方案 A）

更符合“分类由站点/管理员统一维护”的常见做法是 **方案 A：仅管理员定义分类**。

实现要点如下（不执行，仅作规划）：

1. **后端**

- 新增 `AdminCategoryController`（如 `@RequestMapping("/admin")`），提供：
 - `POST /admin/categories` 创建
 - `PUT /admin/categories/{id}` 更新
 - `DELETE /admin/categories/{id}` 删除（逻辑删除与 Article 一致）
- 上述接口统一通过现有 JWT 校验 + 管理员角色校验（与 `AdminArticleController` 一致）。
- `CategoryService` 增加 `createCategory`、`updateCategory`、`deleteCategory`（内部可复用 MyBatis-Plus / BaseMapper）。

2. **前端 - 分类管理页**

- 在个人中心中，当 `activeMenu === 'categories'` 时，不再显示“功能开发中”，改为：
 - 仅管理员可见/可操作（或仅管理员可见完整 CRUD，普通用户可只读列表，按你需求定）。
 - 列表展示现有分类（调用 `getCategories()`），支持新增、编辑、删除（调用现有 `createCategory`/`updateCategory`/`deleteCategory`）。
- 新建/编辑可用弹窗或内联表单，字段至少：名称、slug、描述、排序等（与 [Category](Chen404Bac/src/main/java/com/chen404/domain/entity/Category.java) 字段对齐）。

3. **前端 - 文章编辑页**

- 分类仍为仅选择，不改为 `allow-create`。
- 若 `categories.length === 0`，可提示：“暂无分类，请先在个人中心 → 分类管理中添加”（若仅管理员能进分类管理，可仅对管理员显示“去添加”链接）。

4. **权限与入口**

- “分类管理”菜单：可对**所有登录用户**显示，但列表/操作根据角色控制（例如仅管理员可增删改）；或仅对**管理员**显示该菜单。
- 与现有「我的文章」「个人信息」等一致：走同一套登录与角色判断（如 `user.role === UserRole.ADMIN`）。

这样，**添加全新分类**的流程就是：管理员登录 → 个人中心 → 分类管理 → 新建分类；写博客时在编辑页的“分类”下拉里即可选择到该新分类。

## 四、若你选择方案 B

若希望**写文章时就能新建分类**，需要：

- 后端：提供 `POST /admin/categories`（或 `POST /categories` 且仅登录用户可调），用于“创建一条分类”。
- 文章编辑页：分类的 `el-select` 改为支持“输入新名称并创建”（如 `allow-create` + 失焦或确认时调 `createCategory` 再刷新列表并选中新项），并决定是否仅管理员可创建。

两种方案可以二选一落地；当前代码结构下，更建议先按 **方案 A** 实现管理员在「分类管理」中维护，再视需要决定是否在编辑页增加“快捷新建”（方案 B 的轻量版，仅管理员可在编辑页新建）。
