# 清单页分类动态展示与「加载更多」方案

## 当前状态

- **[Category.vue](Chen404Fro/src/views/Category/Category.vue)**：使用 `mockCategories`，网格为 `repeat(auto-fill, minmax(280px, 1fr))`（自适应列数），文章数用 `Math.floor(Math.random() * 20) + 1` 假数据。
- **后端**：`GET /categories` 返回**全部分类**（无分页），[Category](Chen404Bac/src/main/java/com/chen404/domain/entity/Category.java) 实体含 `articleCount`（若 Mapper 或 Service 有统计则接口会带出）。
- **前端 API**：已有 [getCategories(withArticleCount)](Chen404Fro/src/api/article.ts) 调用 `GET /categories`。

## 方案建议

- **布局**：每行 3 个、首屏 9 个、底部「加载更多」每次再展示 9 个，整体左对齐（可与首页一致用 `DefaultLayout` 的容器，无需额外左移）。
- **数据策略**：  
- **推荐**：前端一次请求 `getCategories()` 拿全量，本地用 `displayCount`（初始 9，点击「加载更多」+9）做前端分页。实现简单，且分类数量通常不大，一次拉取即可。  
- **可选**：若后续分类非常多（如上百），再为后端增加 `GET /categories?page=1&size=9` 分页，前端按页请求（本次不实现）。

## 实现要点

1. **数据源与状态**

- 移除 `mockCategories`，在 `onMounted` 中调用 `getCategories()`，存入 `categories`。
- 新增 `displayCount = ref(9)`，模板只渲染 `categories.slice(0, displayCount)`。
- 「加载更多」：`displayCount += 9`；若 `displayCount >= categories.length` 则隐藏按钮或改为「没有更多了」。

2. **布局**

- 桌面端固定为 3 列：`grid-template-columns: repeat(3, 1fr)`；移动端可改为 1 列或 2 列（如 `max-width: 768px` 时 `repeat(1, 1fr)` 或 `repeat(2, 1fr)`），与当前 280px 最小宽度错开，以「每行 3 / 2 / 1」为主。

3. **文章数**

- 使用后端返回的 `articleCount`：`{{ category.articleCount ?? 0 }} 篇文章`，不再用随机数。

4. **加载与空状态**

- 请求中显示 loading（如骨架或文案「加载中…」），请求失败提示错误。
- 若 `categories.length === 0` 且非加载中，展示空状态（如「暂无分类」）。

5. **样式与一致性**

- 可与首页统一：卡片使用现有 `category-card` 或复用 UnoCSS 的 `jp-card` 等，保持圆角、阴影、悬停与主题色一致。

## 涉及文件

- **[Chen404Fro/src/views/Category/Category.vue](Chen404Fro/src/views/Category/Category.vue)**：改为调用 `getCategories()`，增加 `displayCount`、加载更多逻辑、loading/空状态，网格改为 3 列（及响应式），文章数改为 `category.articleCount ?? 0`。
- 后端无需改动（继续使用 `GET /categories`）；若将来需要分页再在 [CategoryController](Chen404Bac/src/main/java/com/chen404/controller/CategoryController.java) 增加 `page/size` 参数。

## 小结

- 你的设计（一行 3 个、首屏 9 个、加载更多 9 个）是合理且易实现的。
- 建议先用「前端全量拉取 + 前端分页」完成清单页，并统一使用后端分类与真实 `articleCount`；若以后分类量很大再考虑后端分页与接口改造。
