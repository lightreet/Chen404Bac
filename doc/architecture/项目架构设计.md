# Chen404 后端架构设计

本文档描述当前代码实现，而不是历史规划。最后同步时间：2026-05-28。

## 1. 架构概览

```text
Vue Frontend
  -> Controller
  -> Service / ServiceImpl
  -> Mapper (MyBatis Plus)
  -> MySQL / Redis / MinIO

AI Frontend
  -> AiChatController / AiArticleController / MusicRadioController / AdminAiConfigController
  -> AiChatService / LlmArticleAssistService / LlmMusicTrackAiSuggestService / AiConfigService
  -> AiScenarioExecutor + ScenarioDefinition
  -> OpenAI-compatible LLM Provider
```

除标准 Controller -> Service -> Mapper 主链路外，当前项目还包含：

- `JwtAuthenticationFilter`：解析 JWT，并把当前用户写入 `SecurityContext`。
- `@RequireAdmin`：管理员方法级权限校验。
- `AccessService`：统一文章可见性、评论权限、文件删除、知友能力等访问判断。
- `TraceIdFilter`、`RequestBodyCacheFilter`：请求链路辅助。
- `LoggingInterceptor`、`SqlPerformanceInterceptor`：日志与性能观测。
- `Flyway`：数据库基线与后续 schema 迁移。
- `FileReferenceService`：统一重建和查询文件引用关系。
- `AiScenarioExecutor`：AI 场景化能力调度。

## 5. 统一响应与鉴权

### 统一响应

```json
{
  "code": 200,
  "message": "success",
  "data": {}
}
```

### 鉴权流程

```text
Login
  -> issue access token + refresh token
  -> frontend stores token
  -> request carries Authorization header
  -> JwtAuthenticationFilter resolves current user and authorities
  -> SecurityContext stores AuthenticatedUser
  -> controller uses @AuthenticationPrincipal / CurrentUserUtil
```

安全补充：

- 登录失败频控由认证服务控制。
- refresh token 支持服务端吊销和轮换黑名单。
- 管理员能力使用 `@RequireAdmin`。
- 旅行地图等半公开能力使用知友信任级别控制。
- 文件删除和内容访问需要经过 `AccessService`。

## 8. 核心业务模块

### 内容与互动

- 文章支持草稿、发布、可见性、评论策略、封面文件引用。
- 分类和标签支持公开查询，分类支持后台分页。
- 点赞、收藏、评论点赞分别落在独立关系表。
- 评论与留言板共用评论体系，按场景展示。

### 站点运行时配置

- `SiteController` 暴露公开站点配置。
- `SiteConfigService` 只返回公开字段给游客。
- AI 私有配置存储在同一 `site_config` 表，但使用 `is_public = 0` 并仅由 admin-only 接口读取。

### 上传与文件引用

- `UploadController` 支持文章图片、封面、站点资源、头像、受信附件、旅行图片。
- `ImageProcessingService` 对文章图、封面、头像等做 WebP 压缩和尺寸控制。
- `TravelMemoryImageMetadataService` 尝试解析旅行图片 EXIF 经纬度和拍摄时间。
- `FileReferenceService` 统一维护 `file_reference`，供后台文件管理判断文件是否被业务引用。

### 受信申请与知友

- 游客或登录用户可提交受信申请。
- 管理员可审核通过或驳回。
- 审核通过后更新用户信任级别。
- 部分页面和接口要求管理员或知友身份。

### 旅行纪念地图

- 公开侧接口仅允许管理员与知友访问。
- 后台接口仅允许管理员维护地点、图片和游记条目。
- 地点支持手动坐标和图片 EXIF 坐标。
- 支持访问时间范围：`visitedAt` / `visitedEndAt`。

### Sakura Radio 音乐电台

- 公开接口返回 `published` 歌曲和公开歌单。
- 管理接口允许管理员维护歌曲、歌单、默认电台和歌单歌曲排序。
- 歌曲状态支持 `draft`、`published`、`archived`。
- 歌词支持 `plain` 和基础 LRC 格式，保存时做 LRC 行格式校验。
- 音频和封面上传后保存歌曲会通过 `SysFileService.convertToPermanent` 标记为 `MUSIC_AUDIO` / `MUSIC_COVER`。
- 歌曲删除会检查歌单引用；已被歌单引用的歌曲需要先从歌单移除。
- 当前没有歌单删除接口，播放统计、收藏、评论和第三方同步也未实现。
- `file_reference` 的统一重建尚未纳入音乐文件引用，音乐文件目前主要依赖 `sys_file.refType/refId` 标记。

### 表情包

- 公开接口下发表情包和表情项。
- 管理员接口支持分页、创建/更新、删除、ZIP 导入。
- 前端的 scene 策略主要在前端处理，后端保留 pack/item 数据能力。

## 9. AI 架构

当前 AI 能力包括：

- 文章摘要与标签生成：`ARTICLE_ASSIST`
- Lyra 女仆聊天：`MAID_CHAT`
- 规则版相关文章推荐：`ARTICLE_RECOMMEND`
- 音乐曲目信息补全：`MUSIC_TRACK_SUGGEST`
- AI 后台配置：`AdminAiConfigController` + `AiConfigService`

分层：

```text
Controller
  -> Business Service
  -> AiScenarioExecutor
  -> ScenarioDefinition
  -> LlmClient
```

当前聊天响应字段同时包含：

- `panelAnswer`：聊天面板完整回答
- `bubbleText`：Live2D 小气泡短文案
- `replyText`：兼容旧前端，当前等于 `panelAnswer`
- `citations`
- `relatedArticles`
- `suggestions`
- `traceId`

AI 详细设计见 [项目 AI 接入设计](项目AI接入设计.md) 与 [AI 女仆后台配置设计](AI女仆后台配置设计.md)。

## 11. 文档维护规则

后端文档维护时优先同步：

- 新增 controller 或 `/admin/**` 接口。
- 新增 Flyway migration。
- `site_config` 公开/私有配置边界变化。
- AI 响应字段或 SSE 事件变化。
- 访问控制边界变化，例如知友权限、管理员权限、文件删除策略。
- 音乐电台数据模型、文件引用、播放/歌单管理边界变化。
