# Chen404 后端架构设计

本文档描述 `Chen404Bac` 当前代码实现的后端结构，而不是历史规划稿。最近一次按代码校准时间：2026-06-12。

## 1. 架构概览

后端当前是一个以 Spring Boot 为核心的单体服务，按“控制器边界 + 服务编排 + 持久化 + 支撑组件”的方式组织：

```text
Controller
  -> Converter
  -> Service
      -> Service Support / Scenario
      -> Mapper
      -> External Infra (Redis / MinIO / Mail / LLM)
  -> Result / PageResult
```

当前设计目标：

- 用统一 REST 契约承接前端所有页面和后台能力
- 让业务逻辑主要落在 service 层，controller 保持薄边界
- 用 `converter` 收敛 DTO / Entity / VO 转换
- 用 `file_reference` 管理上传文件生命周期
- 用场景化 AI 应用层收敛 Lyra、文章辅助、推荐、音乐补全等能力

## 3. 控制器边界

### 内容与站点

- `ArticleController`：文章列表、详情、我的文章、点赞、收藏、推荐、归档、CRUD
- `CategoryController` / `AdminCategoryController`：分类公开查询与后台分页/CRUD
- `TagController`：标签列表与详情
- `CommentController`：评论、留言板、最新评论、审核、点赞
- `HomeController`：首页聚合数据、站点统计
- `SiteController`：Banner、站点配置、站点成员与公开用户资料

### 认证与权限

- `AuthController`：登录、注册、验证码、刷新 token、用户信息、资料修改、密码修改、登出
- `TrustRequestController`：好友申请、后台审批、邮件审批入口
- `AdminUserController`：知友等级维护

### 文件与资源

- `UploadController`：文章图片、封面、站点资源、头像、旅行图片、音乐音频/封面、附件上传与文件删除
- `AdminFileController`：文件列表、详情、统计
- `EmojiController`：表情包公开接口与后台维护

### 功能专题

- `TravelMemoryController`：旅行纪念地图查询与管理
- `MusicRadioController`：Sakura Radio 公开播放、歌曲/歌单维护、AI 曲目信息补全
- `AiArticleController`：文章摘要与标签生成
- `AiChatController`：Lyra 同步/流式聊天、会话恢复
- `AdminAiConfigController`：AI 后台配置读取、保存、连接测试

## 4. 统一响应与鉴权

### 统一响应

绝大多数接口返回：

```json
{
  "code": 200,
  "message": "success",
  "data": {}
}
```

分页接口统一返回 `PageResult<T>`，由前端手写 API 层统一解包。

### 鉴权流程

1. 登录成功后返回 `token` 与 `refreshToken`
2. 前端后续请求通过 `Authorization: Bearer <token>` 访问
3. `JwtAuthenticationFilter` 解析 token 并写入 `SecurityContext`
4. 控制器通过 `@AuthenticationPrincipal` 或 `CurrentUserUtil` 读取当前用户
5. 管理员能力通过 `@RequireAdmin` 和 `AccessService` 校验
6. 知友能力由 `AccessService` 结合 `UserTrustLevelEnum` 判定

权限的最终裁决始终在后端完成，前端守卫只负责体验层拦截。

## 7. 核心业务模块

### 7.1 内容与互动

由 `ArticleServiceImpl`、`CommentServiceImpl`、`CategoryServiceImpl`、`TagServiceImpl` 等实现。

当前特点：

- 内容列表/详情与“我的内容”共用统一文章模型
- 点赞、收藏、评论点赞均有独立关系表
- 推荐文章能力已经进入 AI 场景层，而不是控制器里直接拼装

### 7.2 上传与文件引用

上传相关能力集中在：

- `UploadController`
- `SysFileServiceImpl`
- `FileReferenceServiceImpl`
- `AdminFileServiceImpl`

文件生命周期：

1. 上传进入 `sys_file`
2. 业务保存时把 URL 转为永久文件
3. `file_reference` 同步业务归属关系
4. 后台文件页通过引用状态、归属类型、文件状态展示治理视图

音乐和旅行纪念地图都会在保存时显式触发“转永久 + 同步引用”。

### 7.3 好友申请与知友访问控制

核心实现：

- `UserTrustRequestServiceImpl`
- `AccessServiceImpl`
- `TrustRequestController`

当前模型：

- 普通用户提交好友申请
- 管理员后台审批或通过邮件入口审批
- 通过后用户获得知友访问能力
- 旅行纪念地图等受限页面通过 `AccessService` 判定是否可见

### 7.4 旅行纪念地图

核心实现：

- `TravelMemoryController`
- `TravelMemoryServiceImpl`
- `TravelMemoryImageMetadataServiceImpl`
- `TravelMemoryConverter`

当前特点：

- 前端 `/memory-map` 是公开入口，但后端列表/详情接口仍只允许管理员或知友访问
- 地点详情同时返回结构化 `stops` 与兼容旧读法的扁平 `entries`
- 当旧数据还没有片段结构时，服务层会构造 legacy fallback stop，避免前端详情页断裂
- 保存时会校验坐标、时间范围、片段照片数量、旅行封面和片段封面顺序
- 当地点本身未显式提供展示坐标时，服务层会按“地点坐标 -> 片段坐标 -> 照片 EXIF 坐标”回填展示坐标
- 旅行图片上传时优先解析 EXIF 中的坐标与拍摄时间

### 7.5 Sakura Radio

核心实现：

- `MusicRadioController`
- `MusicRadioServiceImpl`
- `MusicTrackAiSuggestService`
- `MusicTrackFileReferenceSyncJob`

当前特点：

- 公开侧支持歌曲列表、歌单列表、歌单详情、默认播放集
- 管理侧支持歌曲 CRUD、状态切换、歌单 CRUD、歌单曲目关系维护、默认歌单设置
- 保存歌曲时会把音频/封面转为永久文件，并同步文件引用
- 删除歌曲前会先移除歌单关系，避免业务阻塞

### 7.6 AI 应用层

核心实现：

- `AiChatServiceImpl`
- `AiConfigServiceImpl`
- `LlmArticleAssistServiceImpl`
- `OpenAiCompatibleLlmClient`
- `service/support/scenario/*`

当前场景包括：

- `ARTICLE_ASSIST`
- `MAID_CHAT`
- `ARTICLE_RECOMMEND`
- `MUSIC_TRACK_SUGGEST`

Lyra 聊天返回结构已支持：

- 面板长回答
- 小气泡短句
- 引用片段
- 相关推荐
- 快捷建议
- SSE 流式事件

## 8. 典型业务流

### 登录与续期

1. `AuthController.login`
2. 返回 `token`、`refreshToken`、用户信息
3. 后续请求由 `JwtAuthenticationFilter` 鉴权
4. 前端 401 时调用 `/auth/refresh`

### 旅行地点创建

1. 前端上传旅行图片到 `/upload/travel-memory-image`
2. 后端解析 EXIF，返回 URL、拍摄时间和可用坐标
3. 前端优先按 `CreateTravelMemoryCommand.stops` 组织片段、照片、封面和时间；旧版扁平 `entries` 仍作为兼容输入保留
4. `TravelMemoryServiceImpl.createLocation`
5. 服务层归一化 stops / entries、补全展示坐标、保存地点与片段照片、转永久并同步文件引用

### 歌曲保存

1. 前端上传音频/封面到 `/upload/music-audio`、`/upload/music-cover`
2. 前端提交 `MusicTrackUpsertCommand`
3. `MusicRadioServiceImpl.createTrack/updateTrack`
4. 转永久文件并同步音乐文件引用

### Lyra 流式聊天

1. 前端请求 `/ai/chat/stream`
2. `AiChatServiceImpl` 编排场景请求
3. `OpenAiCompatibleLlmClient` 拉取模型流式输出
4. 后端通过 SSE 分步发出 `session`、`message_start`、`delta`、`citation`、`related_articles`、`suggestions`、`done`

### AI 后台配置保存

1. 管理端读取 `/admin/ai/config`
2. 保存时提交 `AiAdminConfigDTO`
3. `AiConfigServiceImpl` 将配置写回站点配置表
4. API Key 读取时只返回脱敏信息，不回传明文

## 9. 后台任务

当前 XXL-JOB 任务：

- `fileReferenceRebuildJobHandler`：重建全量文件引用
- `fileCleanupJobHandler`：清理文件
- `musicTrackFileReferenceSyncJobHandler`：重建音乐曲目文件引用

这些任务主要用于文件治理和历史数据修复，不影响主业务接口的在线读写路径。
