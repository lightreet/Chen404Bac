# AI 流式接口资源边界

`/ai/chat/stream` 在创建会话、写入用户消息之前检查功能开关与并发配额。默认每进程最多 8 个请求，每个已登录用户最多 2 个；匿名请求共同使用 2 个名额，不能通过更换客户端 visitorId 绕过。超额或执行器关闭时返回 HTTP 429。配额覆盖等待执行、上下文准备、模型调用和结果写入，工作线程真正退出后才释放。

Spring 管理固定大小的工作线程池、有界队列和超时调度器。`app.ai.stream` 下可配置：

| 配置 | 默认值 | 含义 |
| --- | --- | --- |
| `max-concurrent` | 8 | 每进程并发请求上限及工作线程数 |
| `max-per-user` | 2 | 每个已登录用户的并发上限 |
| `max-anonymous` | 2 | 匿名请求合计并发上限 |
| `total-timeout-ms` | 120000 | 从准入开始计算的 SSE 总时长 |
| `idle-timeout-ms` | 30000 | 上游响应头或响应体没有数据的最长等待时间 |
| `max-response-chars` | 32768 | 累计输出字符上限 |

上游单次调用同时受模型请求超时约束，取其与流式总时长配置的较小值。取消会主动取消 HTTP Future、关闭输入流并中断工作线程；每 50 毫秒独立检查总时长、空闲时长和兼容回调的取消状态，不再等待 `readLine` 返回后才检查。SSE 单行限制为 65536 字符，Responses 兼容路径的原始响应体限制为 262144 字符，避免异常上游使缓冲区无限增长。

MVC 完成、错误和超时回调均连接到取消作用域，应用关闭时取消活跃上游请求。浏览器断连由 Servlet 容器通知后执行取消；上游静默期间即使容器尚未观察到断连，也受空闲与总时长限制。超时或断开后的未完成生成不写入助手回复。

这些配额是每进程限额。部署多个实例时，总并发上限是各实例限额之和；需要整个集群共享用户配额时，应在网关或 Redis 中增加统一准入。

本地 HTTP 测试覆盖响应头/响应体阻塞、两种协议的空闲超时、持续输出下的总超时、主动取消、未换行长数据和累计输出上限；MVC 测试验证断开回调、禁止功能无写入、并发拒绝和成功/取消后的资源释放，不调用真实模型服务。
