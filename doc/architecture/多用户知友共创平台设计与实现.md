# Chen404 多用户知友共创平台设计与实现

> 文档状态：当前实现说明  
> 最后核对：2026-07-27  
> 适用分支：前后端 `feat/multi-user-creator-platform`  
> 取代文档：原《多用户知友共创平台设计方案》《多用户知友共创平台测试审查报告》《多用户受保护文件迁移运行手册》

## 1. 结论

本轮多用户改造的核心功能已经完成：

- 启用中的管理员和知友可以发布、编辑和删除自己的文章、旅行地点与音乐。
- 管理员仍保留全站内容管理能力。
- 文章、旅行地点、音乐都建立了明确的所有者字段和服务端鉴权。
- “创作中心”已经并入个人中心的“我的创作”，统一管理文章、旅行与音乐。
- 旅行地图支持按用户展示旅行地点。
- 成员可以选择是否公开个人资料和邮箱。
- 站点所有者可以在后台消息中心查看功能上线后的新增文章、旅行地点、音乐和知友申请。
- 新上传的文章、旅行、音乐与知友申请文件进入保护存储，通过业务权限和短时票据访问。
- 生产环境提供按模块开关，可以分别开放文章、旅行、音乐创作与管理员消息。

历史数据不需要执行对象存储迁移，保持现有公开状态。这是当前产品决定，不是遗漏：

- 历史 `sys_file` 继续使用 `PUBLIC` 存储范围。
- 历史 MinIO 对象不复制到保护桶。
- 历史业务内容中的旧 URL 不替换。
- 历史文件仍可按原公开地址访问。
- 新功能上线后的受保护类型文件才进入保护桶。

需要注意：如果以后希望把某一份历史文件真正改为私密或仅知友可见，必须重新上传该文件或另做定向迁移；只修改文章或旅行地点的可见性，不能撤销已经公开过的旧对象 URL。

因此，“多用户共创改造完成”指代码和数据库结构已经具备完整的核心能力。生产发布仍需执行常规数据库备份、Flyway 迁移验证、环境变量配置和真实环境冒烟测试，但不再以“迁移全部历史文件”为发布前置条件。

## 2. 产品边界

### 2.1 用户角色

| 身份 | 定义 | 主要权限 |
| --- | --- | --- |
| 游客 | 未登录访问者 | 查看公开文章、公开旅行地点、已发布音乐和公开成员资料 |
| 普通登录用户 | 已登录但不是知友或管理员 | 查看公开内容和登录可见文章，管理个人资料 |
| 知友 | 账号启用且 `trustLevel=FRIEND` | 获得文章、旅行、音乐创作能力，并可查看知友可见内容 |
| 管理员 | 账号启用且具备管理员角色 | 获得全部创作能力和全站内容管理能力 |
| 站点所有者 | 配置项 `app.site-owner-user-id` 指定的账号，当前默认为 `1` | 接收后台业务消息；作为历史归属无法推断时的最终回退 |

站点所有者、管理员和内容所有者是三个不同概念：

- 站点所有者用于确定站点主人和后台消息接收者。
- 管理员是授权角色，可以管理全站内容。
- 内容所有者是文章作者、旅行地点创建者或音乐贡献者。

站点所有者 ID 为 `1` 无需为了本次改造而更换，也不会把全部历史内容强制归给账号 `1`。

### 2.2 能力编码

后端统一返回以下能力编码，前端只用它们控制入口显示和路由提示，最终授权仍由后端完成：

| 能力 | 含义 |
| --- | --- |
| `friend-content:view` | 查看知友可见内容 |
| `article:create` | 创建和管理本人文章 |
| `travel:create` | 创建和管理本人旅行地点 |
| `music:create` | 创建和管理本人音乐 |

启用中的知友和管理员拥有上述能力。账号禁用、知友关系撤销或管理员关闭对应共创开关后，知友的写能力会在下一次请求中失效；运行时功能开关不收回启用中管理员的创作与修复能力。

### 2.3 撤权规则

内容所有权不因用户降级而改变，但写权限会立即收回：

- 知友降级为普通用户后，仍是历史内容的作者或贡献者。
- 降级用户不能继续修改或删除需要创作能力的历史内容。
- 禁用账号不能继续执行创作写操作。
- 管理员必须处于启用状态，不能仅凭过期登录态绕过服务层授权。

## 3. 总体架构

多用户能力沿用现有前后端分层，没有另建独立子系统：

```text
Vue 路由与业务页面
    │
    ├─ 登录态、能力提示、个人中心创作管理
    └─ 调用文章 / 旅行 / 音乐 / 文件 / 消息 API
    │
Spring MVC Controller
    │
    ├─ 解析当前登录用户
    └─ 传递操作者 ID，不接受前端伪造作者
    │
业务 Service + AccessService
    │
    ├─ 校验账号状态、角色、能力、资源所有权和可见性
    ├─ 写入业务数据与文件引用
    └─ 事务提交后发布管理员消息
    │
MySQL + Redis/JWT + MinIO
    ├─ MySQL：内容归属、资料隐私、消息、文件元数据
    ├─ JWT：登录鉴权与受保护文件短时票据
    └─ MinIO：公共桶与保护桶
```

关键原则：

1. 前端能力判断只改善体验，不代替后端鉴权。
2. 创建接口的作者或贡献者只能来自当前登录用户。
3. 更新和删除必须同时校验资源所有权与当前创作能力。
4. 管理员代管通过管理员权限显式放行。
5. 新文件先临时上传，业务保存时再绑定到具体资源。
6. 管理员消息在主事务成功提交后写入，消息失败不回滚内容。

## 4. 内容归属与可见性

### 4.1 归属字段

| 内容 | 所有者字段 | 创建规则 | 更新规则 |
| --- | --- | --- | --- |
| 文章 | `article.author_id` | 固定为当前登录用户 | 保留原作者，不接受前端改作者 |
| 旅行地点 | `travel_memory_location.created_by` | 固定为当前登录用户 | 保留原创建者，`updated_by` 记录当前操作者 |
| 音乐 | `music_track.contributor_id` | 固定为当前登录用户 | 保留原贡献者 |
| 文件 | `sys_file.user_id` | 固定为上传者 | 业务绑定时校验上传者 |

管理员编辑他人内容不会改变原所有者。

### 4.2 文章可见性

文章支持：

| 可见性 | 游客 | 登录用户 | 知友 | 所有者/管理员 |
| --- | --- | --- | --- | --- |
| `PUBLIC` | 可见 | 可见 | 可见 | 可见 |
| `LOGIN` | 不可见 | 可见 | 可见 | 可见 |
| `FRIEND` | 不可见 | 不可见 | 可见 | 可见 |
| `PRIVATE` | 不可见 | 不可见 | 不可见 | 可见 |

草稿不进入普通公开列表，所有者和管理员可以通过管理接口查看。

### 4.3 旅行地点可见性

旅行地点支持公开和知友可见两类业务可见性，同时受内容状态控制：

- 普通地图只展示状态允许且当前访问者有权查看的地点。
- 所有者和管理员可以在个人管理接口中查看可管理记录。
- 地图查询支持 `creatorId`，用于只展示某一成员的旅行图层。
- 创建者信息和当前用户可编辑、可删除状态随返回模型提供。

### 4.4 音乐可见性

音乐状态为：

- `draft`：草稿，仅贡献者和管理员可管理。
- `published`：已发布，进入音乐馆公开列表和播放链路。
- `archived`：已归档，不进入公开播放列表。

音乐不设置管理员审核流程。知友可以保存草稿或直接发布，管理员可以因内容、版权或存储原因编辑、归档或删除。

当前音乐表单保留歌词来源说明，但没有独立的结构化版权确认字段，也没有投稿审核队列。若未来开放到更大用户范围，再评估增加来源类型、授权说明或发布确认。

## 5. 文章共创

### 5.1 已实现能力

- 知友和管理员可以新建文章。
- 支持草稿和直接发布。
- 文章作者由后端根据当前登录用户写入。
- 所有者和管理员可以编辑、删除。
- 非管理员不能设置站长级置顶或推荐属性。
- 首次发布时间只在历史值为空时写入，重新发布不会覆盖首次发布时间。
- 创建草稿产生 `ARTICLE_CREATED` 消息。
- 直接发布或首次从草稿变为发布产生 `ARTICLE_PUBLISHED` 消息。
- 文章正文文件和封面在保存时绑定到文章。

### 5.2 主要接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/articles` | 按当前访问者权限查询文章 |
| `GET` | `/api/articles/{id}` | 查询有权查看的文章详情 |
| `GET` | `/api/articles/mine` | 查询当前用户文章，支持标题、状态和分页 |
| `POST` | `/api/articles` | 创建本人文章 |
| `PUT` | `/api/articles/{id}` | 所有者或管理员更新 |
| `DELETE` | `/api/articles/{id}` | 所有者或管理员删除 |

原有点赞、收藏、热门、推荐、归档和相邻文章接口继续保留，并受文章可见性约束。

## 8. 个人中心与成员主页

### 8.1 我的创作

创作管理已经并入 `/profile`，不再在顶部导航中保留独立“创作中心”。

- `/studio` 仅作为旧地址兼容，重定向到 `/profile?tab=creations&content=articles`。
- “我的创作”包含文章、旅行、音乐三个页签。
- 页签右侧主按钮随内容变化：写文章、记旅途、传音乐。
- 搜索框从左到右紧邻状态筛选，控件高度统一。
- 文章支持按标题搜索，并支持全部、草稿、已发布筛选。
- 旅行支持按地点、城市等信息搜索。
- 音乐支持按曲名、歌手、专辑等信息搜索。
- 默认分页：文章每页 5 条，旅行每页 10 条，音乐每页 10 条。
- 能力被撤销后，历史记录仍可查看，但创建、编辑和删除入口按权限收回。

### 8.2 公开成员资料

个人资料增加：

- `profileVisible`：是否出现在公开成员列表和成员主页。
- `emailPublic`：是否在资料公开时同时展示邮箱。

规则：

- 资料未公开时，不进入公开成员列表，公开成员详情接口也不返回该用户。
- 关闭资料公开会同时使公开邮箱失效。
- 邮箱默认不公开。
- 资料设置说明使用标题旁提示图标，开关外层不再增加重复边框。

当前公开成员主页展示：

- 基本资料。
- 公开文章。
- 公开旅行足迹。

音乐上传和个人音乐管理已经完成，但当前公开成员主页没有单独的音乐贡献列表。这是当前界面边界，不影响音乐馆公开播放与个人创作管理。

## 9. 管理员消息中心

### 9.1 记录范围

消息表只记录功能上线后的新业务事件，不补历史消息：

| 事件 | 触发时机 |
| --- | --- |
| `ARTICLE_CREATED` | 新建文章草稿 |
| `ARTICLE_PUBLISHED` | 直接发布或首次发布文章 |
| `TRAVEL_MEMORY_CREATED` | 新建旅行地点 |
| `MUSIC_TRACK_CREATED` | 新建音乐草稿 |
| `MUSIC_TRACK_PUBLISHED` | 直接发布或首次发布音乐 |
| `TRUST_REQUEST_CREATED` | 提交知友申请 |

消息接收人是 `app.site-owner-user-id` 指定的站点所有者，当前默认为用户 `1`。

### 9.2 一致性

业务服务只发布领域事件，消息监听器使用：

- `AFTER_COMMIT`：业务事务成功提交后执行。
- `REQUIRES_NEW`：消息使用独立事务写入。
- `dedupe_key` 唯一索引：防止重复消息。

消息写入失败会记录日志，但不会回滚已经成功创建的文章、旅行地点、音乐或知友申请。

### 9.3 管理端体验

- 管理员登录后，顶部头像显示未读数量，超过 99 显示 `99+`。
- 头像菜单和移动端菜单可以进入 `/admin?tab=notifications`。
- 管理后台左侧“消息中心”同步显示未读数量。
- 消息列表支持全部、未读、已读和事件类型筛选。
- 默认每页 20 条。
- 支持单条已读、全部已读和删除。
- 点击消息可以跳转到文章、旅行地图或音乐管理页面。
- 前端只在页面可见时每 60 秒刷新未读数，页面重新可见时立即刷新。

### 9.4 消息接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/admin/notifications` | 分页查询站点所有者消息 |
| `GET` | `/api/admin/notifications/unread-count` | 查询未读数 |
| `PUT` | `/api/admin/notifications/{id}/read` | 标记单条已读 |
| `PUT` | `/api/admin/notifications/read-all` | 全部已读 |
| `DELETE` | `/api/admin/notifications/{id}` | 删除消息 |

## 10. 文件安全

### 10.1 新上传文件

以下新上传文件进入保护桶：

- `ARTICLE_CONTENT`
- `ARTICLE_COVER`
- `TRAVEL_MEMORY_IMAGE`
- `MUSIC_AUDIO`
- `MUSIC_COVER`
- `TRUST_REQUEST_ATTACHMENT`

头像、站点素材和首页资源等仍使用公共桶。

保护文件访问链路：

1. 上传时由后端决定公共桶或保护桶，前端不能自行指定。
2. `sys_file` 记录 `storage_scope` 和实际 `bucket_name`。
3. 数据库保存稳定地址 `/api/files/{id}`。
4. 上传响应和业务读取可以附带短时访问票据。
5. `GET /api/files/{id}` 校验票据或当前用户业务权限。
6. 校验成功后生成短时 MinIO 预签名地址并重定向。
7. 默认票据和预签名有效期为 5 分钟。

保护桶不允许匿名读取。

### 10.2 文件绑定安全

临时文件转为永久业务文件时，后端校验：

- 文件 ID 与提交 URL 是否一致。
- 文件是否存在且未删除。
- 引用类型是否与业务字段匹配。
- 文件是否处于允许绑定的临时状态。
- 临时文件是否过期。
- 上传者是否为当前操作者。
- 文件是否已被其他业务占用。
- 同一业务重复绑定是否属于幂等操作。

这可以阻止用户提交其他成员的 `fileId` 或 URL，将他人的文件认领到自己的内容。

### 10.3 历史文件最终决策

历史文件继续公开，不执行原计划中的全量对象迁移：

| 项目 | 当前决策 |
| --- | --- |
| 历史 `sys_file.storage_scope` | 保持迁移默认值 `PUBLIC` |
| 历史对象所在桶 | 保持原公共桶 |
| 历史业务 URL | 不替换 |
| 历史匿名访问 | 保持现状 |
| 新受保护类型上传 | 写入保护桶 |
| 将来个别历史文件收紧 | 重新上传或执行定向迁移 |

因此，不再需要“历史对象清点、复制、引用切换、延迟删除”运行手册，也不把历史文件迁移列为生产开放前置条件。

## 11. 数据库迁移与历史归属

### 11.1 `V2026072701__multi_user_creator_platform.sql`

该迁移完成：

- 旅行地点 `created_by` 空值回填。
- 旅行地点 `updated_by` 空值按创建者回填。
- 创建旅行地点创建者索引。
- 音乐新增并回填 `contributor_id`。
- 创建音乐贡献者索引。
- 创建空的 `admin_notification` 表及查询、去重索引。

音乐历史贡献者按以下顺序推断：

1. 音频文件记录的上传者。
2. 封面文件记录的上传者。
3. 音频 URL 匹配到的文件上传者。
4. 封面 URL 匹配到的文件上传者。
5. 仍无法推断时回退到站点所有者用户 `1`。

文章原有 `author_id` 不被覆盖；旅行地点已有创建者不被覆盖。

迁移中的 `BINARY expr is deprecated` 是 MySQL 对未来语法变更的弃用警告，当前迁移仍可成功执行。它用于跨不同排序规则按字节比较历史音乐 URL，不代表迁移失败。应以 Flyway 的 `Successfully applied` 和最终版本号为准。

## 12. 配置与发布

### 12.1 配置项

启动期和基础设施配置继续使用环境变量：

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `APP_SITE_OWNER_USER_ID` | `1` | 站点所有者和消息接收者 |

日常运营需要调整的功能开关存放在 `site_config` 私有配置项中，由“后台 → 站点配置 → 功能开关”即时维护：

| `site_config.config_key` | 默认 | 说明 |
| --- | --- | --- |
| `feature.collaboration.article_creation_enabled` | 关闭 | 知友文章创作 |
| `feature.collaboration.travel_creation_enabled` | 关闭 | 知友旅行创作 |
| `feature.collaboration.music_creation_enabled` | 关闭 | 知友音乐创作 |
| `feature.admin_notification.enabled` | 关闭 | 管理员消息中心 |

功能开关只影响新的业务请求，不需要修改服务器文件或重启后端。配置项保持 `is_public = 0`，前台只通过当前用户的能力编码感知最终授权状态。
知友写入默认关闭，延续生产发布保护策略；完成部署验证后再由管理员逐项开启。管理员自身的维护能力不受这些共创开关影响。

### 12.2 建议发布步骤

1. 备份生产数据库并确认可回滚。
2. 确认 JDK 17、MySQL、Redis 和 MinIO 配置。
3. 配置公共桶与保护桶名称，并确认保护桶不可匿名读取。
4. 启动后端，让 Flyway 应用 `2026072701`、`2026072702` 和 `2026081001`。
5. 确认 Flyway 最终版本和应用健康状态。
6. 使用管理员和知友账号分别验证文章、旅行、音乐的创建与越权拒绝。
7. 验证站点所有者头像未读数和消息跳转。
8. 验证新受保护文件不能通过 MinIO 匿名直链访问。
9. 在管理后台确认文章、旅行、音乐和消息开关符合当前发布范围。

无需暂停站点去迁移历史文件。

### 12.3 回退

如某一模块上线后出现问题：

- 在管理后台关闭对应业务开关，保存后立即生效。
- 如果管理后台暂时不可用，可直接修正 `site_config` 对应私有键并重启服务刷新实例缓存。
- 不回滚已成功执行的 Flyway 迁移。
- 不删除归属字段、隐私字段、消息表或文件范围字段。
- 不把已有内容改回无所有者状态。

关闭功能开关只停止新的知友写入，不影响公开内容读取和管理员修复。
