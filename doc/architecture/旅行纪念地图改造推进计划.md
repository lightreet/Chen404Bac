# 旅行纪念地图改造推进计划

> 状态：历史推进计划，当前代码已完成阶段 1 的 SVG 缩放、滚轮和拖拽体验优化，并已推进阶段 3/4 的本地城市/省级 GeoJSON 加载与自定义 SVG 渲染。
> 目标：在不破坏现有录入、权限和展示链路的前提下，分阶段把旅行地图从“基础可用”推进到“精致可浏览、坐标准确、可长期演进”。

## 1. 当前判断

当前旅行地图已经具备继续升级的基础：

- 后端已有旅行地点主表、照片子表、权限控制、上传解析、文件引用维护。
- 前端已有 `/memory-map`、详情页、创建页、编辑页，以及展示模式和后台选点模式共用的 `TravelMemoryMap`。
- 当前主要短板已从“前台地图展示内核缺市级边界”转为“城市 GeoJSON 的体积、许可证、加载失败观测、城市名匹配和移动端性能需要持续验收”。缩放、滚轮和拖拽平移能力已经补齐。

因此改造不建议推倒重来。推荐保留现有后端接口和后台高德选点能力，优先升级前台展示体验。

## 2. 阶段划分

### 阶段 0：分支与边界确认（历史步骤）

目标：

- 前后端统一进入专题分支。
- 保留当前未提交变更，不回退、不清理。
- 明确第一轮不改数据库、不改接口契约。

验收：

- 后端和前端在同一专题分支。
- 当前功能不做行为改动。

### 阶段 1：补齐当前 SVG 地图浏览能力（已完成）

目标：

- 在现有 `@svg-maps/china` 展示模式上增加拖拽、滚轮缩放和平移重置。
- 将最大缩放提升到约 `2.8`。
- 避免拖拽和 marker 点击互相误触。

范围：

- 主要改动 `Chen404Fro/src/components/TravelMemoryMap/TravelMemoryMap.vue`。
- 不影响 `pickerMode` 下的高德地图选点。
- 不改后端。

验收：

- 鼠标滚轮可以缩放地图。
- 鼠标左键按住可以拖动地图。
- 重置按钮恢复缩放和平移。
- 点击地点仍能切换右侧详情。
- 移动端至少保持可点击、可按钮缩放和可重置。

### 阶段 2：统一坐标系统边界

目标：

- 明确前台展示坐标统一使用 WGS84。
- 高德地图选点得到的 GCJ-02 坐标在提交前转换为 WGS84。
- 如调用高德逆地理编码，则按高德要求使用 GCJ-02。

范围：

- 新增前端坐标转换工具，例如 `Chen404Fro/src/utils/coordinate.ts`。
- 调整创建/编辑页的选点保存逻辑。
- 保持现有接口字段不变。

验收：

- EXIF 坐标仍能回填地点坐标。
- 高德选点保存后，数据库中的地点展示坐标按 WGS84 约定保存。
- 逆地理编码不因坐标转换而失效。

### 阶段 3：确认并引入市级 GeoJSON 数据（已完成基础接入，待补发布说明）

目标：

- 选择合法来源的中国市级 GeoJSON 数据。
- 记录数据来源、许可证、版本和简化策略。
- 处理后的地图数据按需加载，避免进入首屏主包。

范围：

- 已将处理后的 GeoJSON 放在 `Chen404Fro/public/maps/`。
- 已新增 `china-city.manifest.json` 记录地图数据来源与版本。
- 已新增 `scripts/build-china-city-map.mjs` 做离线构建。

验收：

- 地图数据来源和许可证可追溯。
- GeoJSON 体积可接受，并在生产环境持续观测。
- `/memory-map` 页面按需加载地图数据。
- 数据加载失败时页面有降级提示，不白屏。

### 阶段 4：展示模式切换到市级 GeoJSON + 自定义 SVG（已完成基础接入）

目标：

- 前台展示模式从省级 SVG 切换到城市/省级 GeoJSON 渲染。
- 保留现有组件输入输出：`locations`、`activeId`、`select`、`pickerMode`。
- 后台选点继续使用高德地图。

范围：

- 已通过 `src/utils/mapData.ts` 加载 manifest、城市边界和省级底图。
- 已使用 `d3-geo` 统一处理边界、marker 和路线。
- 已增加城市区域高亮、选中态和 hover 态。

验收：

- 前台地图不依赖高德展示，无第三方地图 Logo。
- 旅行地点 marker 正确显示。
- 选中地点、路线和右侧详情保持联动。
- 地图支持缩放、拖拽、重置。
- 未匹配城市区域时仍显示 marker，不阻断页面。

### 阶段 5：城市匹配与联动增强

目标：

- 通过城市名归一化提高 GeoJSON 匹配成功率。
- 点击照片墙时同步选中地图地点。
- 选中地图点时照片墙可滚动或高亮到对应卡片。

范围：

- 前端增加城市名归一化工具和少量 alias 配置。
- 不立即新增数据库字段。
- 如果真实数据匹配失败较多，再评估新增 `province_code` / `city_code`。

验收：

- 常见城市名差异可以匹配，例如 `厦门` 与 `厦门市`。
- 匹配失败不报错。
- 地图、右侧详情、照片墙选中态一致。

## 3. 后端改造原则

近期后端保持轻量：

- 不新增地图接口。
- 不立即新增行政区划码字段。
- 不批量转换历史坐标。
- 保持旅行地点和照片接口契约稳定。

后续触发条件：

- 如果城市区域高亮必须稳定命中，再新增 `province_code` / `city_code`。
- 如果历史坐标来源无法判断但偏移明显，再新增 `coordinate_system` 或做管理员确认式修正。

## 4. 风险清单

- GeoJSON 许可证不清晰：引入前必须确认来源和授权。
- GeoJSON 体积过大：需要简化、字段裁剪和按需加载。
- 坐标系混用：市级地图升级前必须先处理 GCJ-02/WGS84 边界。
- 拖拽误触 marker：需要移动阈值和事件隔离。
- 城市名匹配不稳定：第一版以 marker 正确为硬验收，区域高亮为增强验收。

## 5. 推荐执行顺序

1. 保留已完成的阶段 1 SVG 缩放、滚轮和拖拽优化作为当前基线。
2. 补齐阶段 2 的坐标标准说明和新增数据验收。
3. 补齐 GeoJSON 数据源和许可证发布说明。
4. 持续观测城市 GeoJSON 体积、加载耗时和移动端性能。
5. 增强城市匹配、区域高亮和照片墙联动。
6. 根据真实数据表现决定是否补后端行政区划字段。
