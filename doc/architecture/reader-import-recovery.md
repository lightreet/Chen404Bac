# 阅读器导入恢复

导入接口在事务内保存书籍和源文件引用，提交后尝试交给有界执行器。队列满时保留 `importing` 状态，恢复器每轮按 ID 分批补投；进程启动也使用同一轮询入口。本实例正在排队或执行的书籍不会重复排队。

执行器在解析前用条件更新获取 `import_token` 和租约，并递增尝试次数。数据库时间决定租约有效性，解析期间每隔租约时长的三分之一续租。内容持久化前使用令牌及有效期查询并锁定书籍行，章节、目录、资源和成功状态一起提交。过期执行器不能登记失败、续租或覆盖新执行器的内容。

损坏文件等明确的输入问题立即终止；基础设施异常延迟重试，默认最多 3 次。进程被终止后，租约到期即可恢复；连续中断超过次数上限的任务转为失败。对外继续使用 `importing` / `ready` / `failed`，无需客户端增加新状态。

`app.reader-import` 的默认配置为：`batch-size=32`、`poll-delay-millis=15000`、`lease-seconds=300`、`max-attempts=3`、`retry-delay-seconds=30`。恢复扫描与续租使用专用调度器，解析使用既有有界线程池。

迁移 `V2026090901__add_reader_import_lease.sql` 增加执行令牌、租约、尝试次数及恢复查询索引。已有导入中记录的租约为空，升级后自动进入恢复扫描。部署应先确保迁移成功；混合运行新旧导入执行器期间，旧版本没有租约保护，应停止旧实例后再开启新版本导入处理。

`ReaderImportLeaseMapperTest` 执行实际迁移与 SQL，覆盖并发认领、租约接管、旧执行器隔离、重试上限和分页扫描；`ReaderImportRecoveryTest` 覆盖队列满后补投、数据库暂时故障与排队去重。解析格式与既有导入流程继续由原有测试覆盖。

成功重试会显式写入本次解析说明（允许为空），清除旧失败说明和租约。`ReaderBookImportTransactionTest` 使用实际 Mapper、审计字段填充器和事务管理器，验证这一空值语义、章节/资源/目录写入失败后的整体回滚与无重复重试，以及解析期间丢失租约后完全停止持久化。
