# 旅行照片手机直传

## 使用流程

电脑在旅行新增/编辑页的封面区或旅途片段照片区点击“手机上传”，生成 15 分钟有效的二维码。手机扫码后无需账号登录，选图预览并确认上传。封面每次一张，片段会话最多 60 张，可以分批追加，单张大小与格式读取 `app.site-runtime` 现有上传限制。HEIC/HEIF 暂不支持，需从相册导出 JPG。

点击“手机上传”直接弹出二维码，只显示目标与上传状态，不在编辑页要求输入地址。电脑约每 2.5 秒读取已完成图片并回填。关闭弹窗不停止接收；结束上传、切换上传目标、离开编辑器时撤销原授权。已有封面需在电脑确认替换。保存前原子停止新上传并合并最后回执；有正在上传的文件时阻止保存，避免漏图。

## API 与安全边界

| 方法与路径（均在 `/api` 下） | 授权与职责 |
| --- | --- |
| `POST /upload/travel-mobile/sessions` | 账号登录且具备旅行创作权限，创建会话 |
| `GET /upload/travel-mobile/sessions/{id}` | 所有者读取结果、刷新桌面在线租约 |
| `DELETE /upload/travel-mobile/sessions/{id}` | 所有者撤销；`requireIdle=true` 用于保存前原子封口 |
| `GET /upload/travel-mobile/public/{id}` | 独立 `X-Upload-Token` 凭证，返回目标和回执，不返回图片地址或 EXIF |
| `POST /upload/travel-mobile/public/{id}/images` | 同一凭证 + multipart `file` / `requestId`，单张幂等上传 |
| `POST /upload/travel-mobile/public/{id}/batches/{batchId}` | 手机在开始整批上传前登记批次，文件请求间隔内也阻止桌面提前保存 |
| `DELETE /upload/travel-mobile/public/{id}/batches/{batchId}` | 手机结束批次，迟到的旧批次请求不会释放新批次 |

- 上传凭证由 32 字节安全随机数生成，Redis 只存 SHA-256 摘要。凭证放在 URL fragment，手机读取后从地址栏移除，在当前标签页 sessionStorage 内保留以支持刷新。HTTP 使用独立请求头，不携带账号 JWT。
- 公共接口只放行明确的方法和路径；创建、轮询及关闭仍需账号鉴权和所有权校验。每次手机读取/上传也重新校验发起者当前旅行创作权限。
- 桌面在线租约为 2 分钟。断网、关闭页面导致续租停止时，手机不能继续上传；迟到的轮询不会复活过期租约。所有响应 `Cache-Control: no-store`。
- 每用户每分钟最多生成 10 次；每会话最多 3 个上传中请求，封面 1 张、片段 60 张。实际图片头、格式、大小及 8000 万像素上限均在存储前校验，不只信任 MIME。
- 手机状态轮询在上传期间携带 `batchId`，续租 3 分钟批次状态；租约不延长二维码的 15 分钟授权。保存检查正在传输的文件和整批状态，手机异常退出后批次租约自动失效，桌面也可主动结束上传。
- `requestId` 固定标识手机队列中的一张图片；成功重试返回原回执，不再入库。Redis CAS 保证并发预占、回执与关闭不互相覆盖。上传尝试 3 分钟无回执后可重试，新尝试使旧尝试不能覆盖结果。
- 会话授权 15 分钟，Redis 回执保留 25 分钟供桌面收尾；手机请求不会延长原始授权。Lua CAS 保持原 TTL。
- 文件以电脑发起者的 userId 和 `TRAVEL_MEMORY_IMAGE` 类型进入既有 `SysFileService`，复用图片处理、受保护存储、临时文件与业务保存时的所有权认领。过期/撤销后的迟到文件保持临时状态，由原清理流程回收。

## 前端生命周期

每个编辑器最多一个活动上传目标，片段使用稳定的客户端标识而非数组下标。重新排序不改变接收目标；删除目标停止会话。手机页面按 sessionId 重建，避免同一路径再次扫码复用旧会话。桌面去重回填，用户删掉的照片不会因后续轮询复活。

## 本地与部署

前后端一起发布后即可使用，无数据库迁移。手机页面和 `/api` 应走同一站点反向代理。Vite 提供 `/api` 到 `127.0.0.1:10404` 的开发代理，可用 `CHEN404_DEV_API_TARGET` 指向隔离测试后端。

二维码完整链接由后端创建接口返回，优先读取 `site_config` 中的 `app.frontend-base-url`，未设置时复用服务器同名配置（生产环境由现有 `APP_FRONTEND_BASE_URL` 提供）。后台“站点配置 → 站点基础信息 → 网站访问地址”可修改覆盖值，留空恢复服务器默认，新会话立即生效。不使用独立的手机上传环境变量，也不从编辑器浏览器的 localhost 推断地址。

手机访问该网站域名上的页面和同源 `/api`，因此该域名下的前后端必须已部署本功能，且与发起会话的后端共享 Redis 会话和文件存储。仅修改本机前端不能让尚未发布的线上页面生效。局域网隔离测试时，在测试后端配置同一个 `app.frontend-base-url` 即可，不需要编辑器中的手工地址输入。

## 代码审查后的修正

- 编辑器用版本号隔离创建、关闭、轮询及二维码绘制的异步结果。离开/切换地点后迟到的创建会被撤销，旧请求不能回填新表单或改变新会话状态。
- 新二维码生成失败时清理新会话和无效二维码；原批次上传中拒绝切换时仍保留原目标的二维码。
- 增加批次租约，修复相邻文件请求之间提前保存的竞态。手机只提示“已上传，请回电脑确认并保存”，不把服务器回执当成电脑保存成功。
- 上传项状态使用兼容原 JSON 小写值的枚举；过期项被替代后，迟到的存储完成不会空指针或覆盖新记录。文件映射使用 MapStruct，并在副本上签发图片票据。
- 地址未修改时，前端不提交覆盖字段，后端也不将环境回退值固化到数据库。容器级超限返回明确的 HTTP 413。
- 手机端合并并发状态查询，选图错误不会被下一轮状态刷新清除。

前端回归入口：`npm run test:travel-mobile`，使用 Node 内置测试运行器与真实 Vue 响应式，覆盖迟到请求、会话切换、二维码失败和最终回执合并。
