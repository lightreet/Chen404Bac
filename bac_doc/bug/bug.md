# Chen404Bac Bug 清单

> 说明：本文件记录后端侧已确认的问题与处理状态，便于后续排查和回归验证。

## 待处理

### 2. 公开文章列表的 `status` 参数对外暴露但被忽略

- 状态：待处理
- 严重级别：高
- 影响范围：`GET /articles`
- 问题描述：当前公开列表接口强制只返回 `PUBLISHED + PUBLIC` 文章，传入的 `status` 参数不会生效，但接口文档仍对外暴露草稿/已发布/回收站状态。
- 影响：调用方可能误以为可以按状态查询，实际行为与接口描述不一致。
- 建议修复：公开接口移除 `status` 参数，或拆分出后台管理列表接口。

### 3. 批量上传使用默认线程池执行阻塞 I/O

- 状态：待处理
- 严重级别：中
- 影响范围：`UploadController.uploadImages`
- 问题描述：批量上传通过 `CompletableFuture.supplyAsync()` 使用默认公共线程池执行文件上传，上传属于阻塞 I/O，在线上可能影响公共线程池中的其他任务。
- 影响：高并发时可能出现吞吐下降、线程争抢或响应抖动。
- 建议修复：改为专用线程池，或限制并发度后串/并行上传。

### 5. 图片校验仅依赖 `contentType`

- 状态：待处理
- 严重级别：中
- 影响范围：图片/封面/头像上传
- 问题描述：当前仅根据 `MultipartFile.getContentType()` 判断是否为图片，缺少文件头或解码层面的服务端校验。
- 影响：理论上可被伪造 MIME 类型绕过，上传非真实图片文件。
- 建议修复：增加文件头校验、图片解码校验，或在存储前做更严格的服务端验证。

### 6. 邻居文章仅按公开文章计算

- 状态：待处理
- 严重级别：低
- 影响范围：`GET /articles/{id}/neighbors`
- 问题描述：即使当前用户可访问某篇登录可见/好友可见文章，其上一篇/下一篇仍只从公开文章中计算。
- 影响：对受限文章的阅读导航不一致，体验与权限模型不完全匹配。
- 建议修复：按“当前访问者可见的文章集合”计算相邻文章，或明确文档说明该接口只基于公开时间线。

### 7. 点赞限流使用进程内内存缓存

- 状态：待处理
- 严重级别：低
- 影响范围：`POST /articles/{id}/like`
- 问题描述：当前限流基于进程内 `ConcurrentHashMap`，在单机博客场景可用，但不支持多实例共享，也会在大量不同 IP 冲击时带来一定内存增长。
- 影响：扩展性一般，多实例部署下限流不一致。
- 建议修复：未来如接入 Redis，可迁移到分布式限流。

### 8. `fillArticlePermissions` 仍存在重复查库空间

- 状态：待处理
- 严重级别：低
- 影响范围：文章详情和权限填充逻辑
- 问题描述：`canManageArticle`、`canCommentArticle` 等方法内部会重复通过 `userId` 查当前用户，权限填充时存在优化空间。
- 影响：正确性不受影响，但会增加部分不必要的数据库查询。
- 建议修复：在一次请求中先加载当前用户，再将 `User` 对象传入各权限判断函数。

### 9. JWT 登出仍为客户端清 token，服务端无法即时失效

- 状态：待处理
- 严重级别：低
- 影响范围：`POST /auth/logout`
- 问题描述：当前 logout 为无状态实现，服务端不会撤销 token。
- 影响：已泄露 token 在过期前仍可能被使用。
- 建议修复：如后续接入 Redis，可增加 token 黑名单或版本号机制。

### 10. `Article.password` 与 `visibility` 的关系未定义

- 状态：待处理
- 严重级别：低
- 影响范围：文章访问控制设计
- 问题描述：数据库和实体里保留了 `password` 字段，同时又引入了 `visibility`，但当前权限逻辑未定义二者关系。
- 影响：后续如果启用密码文章，容易与现有可见性模型冲突。
- 建议修复：明确设计是“二选一”还是“可叠加”，并在访问逻辑中统一实现。

## 已修复

### 1. 头像上传未进入 SysFile 跟踪

- 状态：已修复
- 严重级别：高
- 原问题：头像上传直接走存储服务，没有 `SysFile` 记录，无法追踪归属，也无法在更换头像时清理旧文件。
- 修复结果：头像上传已改为 `SysFile.RefType.AVATAR` 方式入库；更新资料时会将新头像转为正式文件并清理旧头像文件。

### 2. 点赞接口没有频率限制

- 状态：已修复
- 严重级别：高
- 原问题：`POST /articles/{id}/like` 可被脚本无限刷赞。
- 修复结果：已增加基于“文章 + 用户 / IP”的限频逻辑，请求过快返回 `429 Too Many Requests`。

### 3. `/comments` 路径全方法公开

- 状态：已修复
- 严重级别：高
- 原问题：评论路径在 JWT 拦截器中整体放开，未来评论写接口容易绕过登录校验。
- 修复结果：`JwtInterceptor` 中 `/comments` 已改为仅 `GET` 公开，写操作默认受 JWT 保护。

### 4. `trust_level` 只能手改数据库

- 状态：已修复
- 严重级别：高
- 原问题：没有管理接口设置用户是否为好友/受信用户。
- 修复结果：已新增管理员接口 `PUT /admin/users/{id}/trust-level`。

### 5. 非管理员可设置 `isTop` / `isRecommend`

- 状态：已修复
- 严重级别：高
- 原问题：普通用户创建或更新文章时可提交置顶/推荐字段，存在越权风险。
- 修复结果：服务端已在创建/更新时强制保护这两个字段，仅管理员可控制。

### 6. 客户端可提交文章互动统计字段

- 状态：已修复
- 严重级别：高
- 原问题：`viewCount`、`likeCount`、`commentCount` 可能被客户端直接覆盖。
- 修复结果：创建时强制归零，更新时保留服务端原值。

### 7. 公开点赞可绕过文章可见性

- 状态：已修复
- 严重级别：高
- 原问题：受限文章理论上也可被公开点赞。
- 修复结果：点赞前已增加 `canViewArticle` 校验，不可见文章不可互动。

### 8. 批量图片上传没有建立文件归属记录

- 状态：已修复
- 严重级别：高
- 原问题：批量上传未创建 `SysFile` 记录，后续无法按所有权删除。
- 修复结果：批量上传已统一改为走 `sysFileService.uploadTempFile()`。

### 9. 无记录文件可按 URL 直接删除存储对象

- 状态：已修复
- 严重级别：高
- 原问题：删除逻辑过宽，存在按 URL 直接删底层对象的风险。
- 修复结果：删除前必须先查到 `SysFile` 记录，并通过所有权校验。

### 10. 认证验证码被直接回传到前端

- 状态：已修复
- 严重级别：高
- 原问题：发送验证码接口曾返回验证码内容，存在明显泄露风险。
- 修复结果：响应中已移除验证码字段。

### 11. `@RequireAdmin` 仍依赖硬编码角色值

- 状态：已修复
- 严重级别：中
- 原问题：管理员判定依赖魔法数字，不稳定。
- 修复结果：已统一改为基于 `role_code = admin` 判断。

### 12. 被禁用用户持旧 JWT 仍可访问受保护接口

- 状态：已修复
- 严重级别：中
- 原问题：只校验 token 有效性，不校验用户实时状态。
- 修复结果：JWT 拦截器和 refresh 接口均已校验账号状态。

### 13. `likeCount` 为空时可能触发空指针

- 状态：已修复
- 严重级别：中
- 原问题：点赞后返回值计算没有兜底。
- 修复结果：已加空值保护。

### 14. 文章密码字段可能被序列化返回

- 状态：已修复
- 严重级别：中
- 原问题：`Article.password` 可能泄露到前端。
- 修复结果：已为该字段添加 `@JsonIgnore`。

### 15. 公开文章列表的 `tagId` 参数未生效

- 状态：已修复
- 严重级别：高
- 原问题：接口签名接收 `tagId`，Swagger 也声明支持标签筛选，但 `ArticleServiceImpl.getArticlePage()` 中没有使用该参数，导致标签筛选实际上无效。
- 修复结果：公开文章分页查询已接入基于 `article_tag` 的标签过滤逻辑。

### 16. 上传/删除接口直接返回底层异常信息

- 状态：已修复
- 严重级别：中
- 原问题：上传和删除文件失败时直接将底层异常信息返回给前端，存在暴露实现细节的风险。
- 修复结果：对外错误响应已改为通用提示，详细异常仅保留在后端日志中。
